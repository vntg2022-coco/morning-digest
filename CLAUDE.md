# CLAUDE.md

Good Morning Digest: a language-learning news service. Users pick a native language and one or more learning languages from 12, and every morning get an email linking to 3 news articles written in their learning language at their level, shown side by side with a native-language translation, with click-to-define words and a vocab list. Site UI copy is English only. The owner communicates in Japanese.

**`docs/SPEC.md` is the agreed product spec** (plans, pricing, trial, LP sections, build order). Read it before product work and keep it updated when decisions change.

## Commands
- `npm run digest:preview -- es:intermediate:en zh:beginner:ja` (or `-- --active`) — builds today's content in Supabase for those editions (learning:level:native), reusing anything that already exists, and writes tappable HTML to `previews/`. Costs real money only for what's missing (~$0.25 to write a learning×level, ~$0.13 per extra native language); the script prints the cost. Run from Claude Code with `env -u ANTHROPIC_BASE_URL` so the SDK talks to the real API.
- `npm run set-key -- NAME` / `npm run check-keys` — set/verify keys in `.env.local` without printing them. Never print or log key values.
- `npm run dev` — dev server on :3000
- `npm run verify` — lint + production build into `.next-verify/`; run before saying a change is done. Use this instead of `npm run build` while the dev server is running (a plain build overwrites the dev server's `.next`).
- `npm run lint` — ESLint (next/core-web-vitals)
- `npm run stripe:setup` — creates the Stripe products/prices (by lookup key) in the mode of `STRIPE_SECRET_KEY`; safe to rerun
- `npm run email:test -- you@example.com` — sends that reader's morning email now (ignores delivery time; still recorded in `deliveries`)

## Stack
- Next.js 14 Pages Router, React 18, plain JavaScript (no TypeScript yet)
- Styling is mostly inline `style={{}}` objects; Tailwind is installed but barely used. Look is modeled on the New York Times site: serif headlines `var(--font-serif)` (Source Serif 4), sans body/buttons `var(--font-sans)` (Libre Franklin), text `#121212`, black square-ish buttons, off-white `#f0eee9` backgrounds, link/accent blue `#326891`. Don't use NYT's own fonts, logo or name.
- Deployed on Vercel from GitHub `vntg2022-coco/morning-digest`, branch `main`.

## State of the code
- Content pipeline in `lib/pipeline/`: `daily.mjs` `ensureEdition()` fills in whatever is missing for a date — the day's 3 stories (`select.mjs`, once per day, excerpts saved in `stories`), articles per learning language × level (`write.mjs`, one Claude call per story), translations per native language (`translate.mjs`). `buildDay()` runs it for all `activeEditions()` (cron `/api/cron/digest`); `/api/prepare` runs it on demand for a reader who has nothing for today (e.g. right after signup). Never reselect a date that already has stories. `reader-preview.mjs` renders a tappable HTML preview. `lib/` uses `.mjs` so the same code runs in Next.js and plain Node scripts.
- The landing page (`pages/index.js`, `components/landing/`) follows SPEC.md. The mailbox/key art in `components/landing/Mailbox.js` is a placeholder SVG to be replaced. `lib/languages.mjs` is the single list of the 12 languages.
- Supabase (project ref `mkrgkeotacpqcainvfyk`): schema in `supabase/migrations/*.sql`, applied with `npm run db:migrate` (Management API, needs `SUPABASE_ACCESS_TOKEN`). Never edit an applied migration; add a new numbered file. RLS is on everywhere: the browser can read/update only its own profile and settings; content, picks, vocab and adding languages go through API routes using `createSupabaseAdmin()` after checking the user and plan (`lib/plans.mjs`).
- Auth: email + password via Supabase Auth with cookie sessions (`lib/supabase/`). `/signup` → email link → `/auth/callback` → `/onboarding` (native language, first learning language + level, time zone, delivery time; `/api/onboarding`) → `/dashboard`. Pages that need a user call `requireUser(ctx)` in getServerSideProps.
- Plans (`lib/plans.mjs`): new signups are on `preview` (no card, Premium features until their next morning delivery, `preview_ends_at`), then `trial` (7 days, starts with a card in build step 6), `standard`, `premium`; expired preview/trial → `inactive`. Languages are never deleted: they form one ordered list (`learning_languages.sort_order`). `listCapacity()` = plan allowance (Standard 1, Premium/trial 2, preview 1) + one per purchased $4.99 add-on; `deliveredCount()` = the whole list on Premium/trial/preview, only the top language on Standard (reordering to switch is unlimited). UI: `components/LanguageList.js` (macOS Preferred Languages style, pointer-event drag); try it without an account at `/dev/language-list` (dev only). `profiles.last_language_swap_at` and `learning_languages.active` are legacy columns (no swap limit anymore; `active` just mirrors delivery).
- Morning email: `lib/delivery.mjs` `deliverMorning()` runs every 15 min (`/api/cron/deliver`, called by GitHub Actions `.github/workflows/deliver.yml` with `CRON_SECRET`, since Vercel Hobby only allows daily crons; repo secrets `APP_URL` and `CRON_SECRET`): readers whose local time is within 3 hours after their `delivery_time` and who have no `sent`/`skipped` row in `deliveries` for that local date get `lib/email/morning.mjs` via Resend (`lib/send-email.mjs`). Missing editions are built first. One-click unsubscribe: signed link `lib/email/links.mjs` → `/api/email/unsubscribe` (sets `email_enabled=false`); Settings has the toggle. Functions are capped at 300s (Hobby). Vercel Hobby is for non-commercial use: move to Pro before charging real money.
- Billing (`lib/billing.mjs`, Stripe; Stripe is the source of truth): `/billing` page; `/api/billing/checkout` (subscription with a 7-day trial the first time, or a one-time $4.99 language slot), `/api/billing/portal` (Stripe customer portal for switching plan, card, cancel). Prices are looked up by `lookup_key` (`npm run stripe:setup` creates them). `syncSubscription()` maps Stripe status → `profiles.plan` (trialing→trial, active/past_due→subscribed plan, ended→inactive). Results are synced when the reader returns to `/billing` and by `/api/stripe/webhook` (for the deployed site). Slot purchases go through the `record_language_slot_purchase` SQL function so each checkout counts once.
- Reader (News box): `/dashboard` (today's 3 stories; Standard picks 1 via `/api/pick`), `/read/[id]` (side-by-side reader, `components/Reader.js`, tap a word → meaning; Premium saves to vocab via `/api/vocab`), `/archive`, `/vocab`, `/settings` (`/api/settings`: delivery, native language, add/activate/pause languages and levels). Who may open a story is decided only in `lib/access.mjs` (`storyAccess`), server-side. Content queries live in `lib/store.mjs`. Billing (Stripe) is build step 6.

## Rules
- Secrets go in `.env.local` (gitignored). Add every new variable to `.env.example`.
- News: store and show summaries plus a link to the original article. Never republish full article text.
- Don't commit to `main` directly; use a branch.
